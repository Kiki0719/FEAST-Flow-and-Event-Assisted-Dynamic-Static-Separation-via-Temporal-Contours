# MERCY Stage-1 RGB/Event Motion Adapter (flow-first)

## Boundary and guarantees
- Preserve original Blender static Part extraction and `binding.labels`. **No Blender animation motion source.**
- Stage A: project canonical G0 centers through Gaussian fixed camera, sample SEA-RAFT flow over a temporal subset. Use depth z-buffer approximations; detect preliminary moving **Gaussian centers**, aggregate to candidate Parts.
- Stage B: existing CoTracker3 tracks check those Part candidates, SEA-RAFT validates trajectory displacement, depth visibility and Event contours are measured. Events are now **corroborating evidence, not a first-stage hard gate**.
- Stage C: intersect confirmed Part IDs with flow-moving Gaussian candidate IDs and export **new** binding NPZ; never overwrite original binding.
- Stage D: original `refine_motion_rgb.py` obtains RGB+Flow SE(3), `video_part_poses.npz` with `delta_g0 (T,P,4,4)`.

## Important limitations
- This method can miss Gaussian centers occluded in first frame. Exact per-Gaussian dynamic index is **not equivalent** to whole rigid Part membership. For full rigid-body animation downstream, one may drive all Gaussians of a confirmed Part, but that broadening must be an explicit later choice.
- Renderer use and MERCY CUDA dependencies must be tested on your server. Camera alignment / Binding correctness are **preconditions**. No synthetic image is proof of correct registration.
- 2D optical flow is insufficient to uniquely identify 3D motion or camera motion. Assumes fixed scene camera and fixed object G0 coordinates.

## Integration commands (run from MERCY root)
```bash
export PYTHONPATH="$PWD:$PYTHONPATH"
export DATA=/root/autodl-tmp/Mono_Data/metronome
export RUN="$PWD/outputs/metronome/new_flow_first"
mkdir -p "$RUN"
# Keep original binding as $RUN/initial-binding.npz (generated by the MERCY binding pipeline)
# Keep SEA-RAFT precomputed flow as $RUN/searaft_flow.npy, video T frames => flow T-1 frames
python -m rgb_part_motion_se3_flow.flow_first_gaussians \
  --g0 "$DATA/corrected_g0.ply" --binding "$RUN/initial-binding.npz" \
  --camera "$RUN/metronome-camera-inspection.json" --flow-npy "$RUN/searaft_flow.npy" \
  --output "$RUN/flow_first"
# Set the CoTracker3 checkpoint path and event NPZ; frame count must match SEA-RAFT flow T-1
python -m rgb_part_motion_se3_flow.event_track_confirm \
  --g0 "$DATA/corrected_g0.ply" --binding "$RUN/initial-binding.npz" \
  --camera "$RUN/metronome-camera-inspection.json" --video "$DATA/metronome.mkv" \
  --events "$DATA/metronome_event.npy" --flow-npy "$RUN/searaft_flow.npy" \
  --flow-candidates "$RUN/flow_first/flow_candidate_parts.json" \
  --pose-init "$RUN/identity-poses.npz" \
  --cotracker-checkpoint /path/to/scaled_offline.pth \
  --frames 50 --output "$RUN/confirmation"
python -m rgb_part_motion_se3_flow.finalize_motion_binding \
  --binding "$RUN/initial-binding.npz" \
  --flow-candidates "$RUN/flow_first/flow_candidates.npz" \
  --confirmation "$RUN/confirmation/motion_confirmation.json" \
  --output "$RUN/confirmed-binding.npz"
# Existing SE3 optimizer output: $RUN/se3_refinement/video_part_poses.npz
python -m rgb_part_motion_se3_flow.mercy_motion_contract \
  --binding "$RUN/confirmed-binding.npz" \
  --poses "$RUN/se3_refinement/video_part_poses.npz"
```

**Do not feed** `tracking_evidence.npz` into `--tracking`; it contains 2D tracks not SE3 poses. `refine_motion_rgb --init identity` works without Blender animation, but its command flags and actual outputs must be verified on the target server.

## Camera and coordinate convention
- Blender Mesh part export uses Blender scene coordinate geometry.
- `registration` maps Blender geometry into canonical G0 world coordinates.
- Motion modules operate on G0 world using the Gaussian fixed camera (OpenGL C2W converted to OpenCV view).
- Never substitute Blender camera for fixed camera in a G0 projection.

## Integration scope
- Includes 13 original Python source files + adapter files. Does not overwrite MERCY core sources.
- The project Motion Export and Viewer are not included in this package; validate exported `delta_g0` and use repository's existing exporter with corresponding Part IDs.
